# Contributing

Thanks for helping build the SEA-AD spatial progression niches project
(Paper 1 of 4). All code contributions are data-free: development and CI
run entirely on synthetic tissues generated by
`seaad_niches.simulate.simulate_tissue`.

## Setup

```bash
git clone https://github.com/hwilner/sea-ad-spatial-progression-niches.git
cd sea-ad-spatial-progression-niches
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
```

Optional extras: `seaad_niches[leiden]` (Leiden clustering backend) and
`seaad_niches[spatial]` (anndata/squidpy interop) are not required for
tests; the k-means fallback is the default in CI.

## Running tests

```bash
python -m pytest -q
```

All tests must pass before opening a PR. Tests must use synthetic data
only; never commit SEA-AD data or derived real-data results (see
`docs/DATA_ACCESS.md`).

## Picking up backlog issues

1. Browse the open issues; each is a task card with **Task**,
   **Dependencies**, **Acceptance criteria**, and **Boundary** sections
   and a `task-key` comment.
2. Check the Dependencies section: tasks labeled `blocked` wait on other
   cards (or on SEA-AD data access) and should not be started early.
3. Comment on the issue to claim it, then open a PR referencing it
   (`Closes #N`).
4. A task is done only when every acceptance criterion is met.

## Code style

- Python >= 3.10, src layout under `src/seaad_niches/`.
- Lint with [ruff](https://docs.astral.sh/ruff/): `ruff check src tests`
  (line length 100, see `pyproject.toml`).
- Pure in-memory, dataset-agnostic implementations: no hard-coded
  dataset constants, no file I/O in `spatial.py` / `niches.py` /
  `progression.py`.
- Document all public function parameters (numpy-style docstrings).

## PR process

1. Branch from `main`; keep PRs focused on one task card.
2. Fill in the PR template (task card reference, acceptance criteria
   checklist, boundary statement).
3. CI (pytest on Python 3.10-3.12) must be green.
4. The repository scientific owner reviews and merges.
